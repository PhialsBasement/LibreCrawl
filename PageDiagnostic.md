# Page Diagnostic Plugin

## Description

A plugin created as a tab at the end next to E-E-A-T tab, after crawling the site based on URL to take issues from Issue tab with better descriptions than in the Issues tab and a 'How to Fix' using AI API keys like OpenAI or Anthrophic for potentially more detailed explanations. After the AI parses a more detailed description (or else it would send nothing should it decide that the description given suffices), a 'Create Ticket' button will have a ticket with a report containing title, description containing summary, responsibility and implementation direction, acceptance criteria and priority in details.

## Features
- New plugin called page diagnostics showing better described issues from Issue tabs, with 'Ask AI' to further explain (if necessary) for the user
- Shows 'Create Ticket' after 'Ask AI' where users send the issue to Azure DevOps boards based on the Azure projects
- Authorizing only users with domain email @culturalinfusion.com to access the site as passwordless with a magic link

## Modified Files

- .env.example = To copy as an .env file for configuration. Additional AI API keys for the page-diagnostic plugin 'Ask AI' feature and AzureDevOps configuration with Org and Email set within  company. PAT (Personal Access Token) will be generated by the user (?)
- src/crawl_db.py = Creating new table for devops tickets with functions to save ticket inside database and check whether ticket is already created so the existing ticket will not be created again.
- src/auth_db.py = Created table for magic link approach for authorization
- src./mail_service.py = Further update when email is used that it will show magic link is sent to said email to access the tool
- web/static/css/styles.css = To accomodate for tabs depending on screen size for multiple screens used by the company.
- web/static/js/app.js =For Azure DevOps Project / Board selectors for more dynamic choice than hardcoded .env stuck on one project
- web/static/js/plugin-loader.js  = Fixing tab overflow on screen changes
page-diagnostic.js = Latest plugin, covering on critical errors, broken links and images, missing meta tags and performance problems specifically with Issues Table focusing where the URL, Category, About the Issue and How To Fix having an Ask AI. Once AI is asked, 'Create Ticket' is found to push the ticket to selected Azure board from Azure project.
- docker-compose.yml = Ensuring even self-hosting in docker during testing phases that only email domains @culturalinfusion could access the tool.
- main.py = Added CATEGORY_ROLE_MAP dict that maps crawl issue categories (Technical, Performance, SEO etc) to the responsible team role. Five new API endpoints: 
    - /api/explain_issue (POST) to call OpenAI GPT-3.5-turbo (used for testing purposes and can be modified) with the issue URL, category, and page context to generate plain-English explanation, step-by-step fix, priority rating and responsible role, once pressing 'Ask AI' to 'AI Ready' with said information
    - api/create_devops_ticket (POST) - creating a Product Backlog Item in Azure DevOps. Builds HTML description and acceptance criteria based on a certain template. Links the item to a parent Feature or Epic supplied by user via Feature and Project dropdown. Saves the ticket ID and URL to local SQLite3 database.
    - /api/devops_ticket/check (POST) = queries local database for existing by URL + issue pairs so existing tickets will show 'Already ticketed' and prevent duplicates.
    - api/devops/projects (GET) = calls Azure DevOps REST API to return all projects in the configured organisation. Feeds the Project dropdown in the plugin
    - api/devops/features (GET) = similar to projects, except for Epics and Features with the number associated to easily find in Azure DevOps
## To Know
- Project and board must be selected before URLs are crawled or else would throw an error that Azure project and board is not chosen.
- 'Ask AI' button has to be clicked in Page-Diagnostic tab in order to access Create Ticket
- Even when 'Ask AI' does not generate extra information, it will still create a ticket based on information available to Azure because it deemed enough information that it cannot be explained further. 
- At .env.example, for authorization, who would be the one that sends the magic link? Need to figure out for that specific configuration when configuring SMTP credentials.
- Personal Access Token (PAT) in .env.example acts as an API key for integration where the PAT owner becomes the backlog owner for all issues assigned to them in Azure Boards.
